Before you start

00

Plan on about 15 minutes. Here's what you need:

WhatWhy
An always-on Linux machine with Docker and its Compose plugin: an old laptop, a mini PC, a home server, or a small VPSYour devices meet here. The panel and your assistant read from it. If it goes down, devices keep collecting and blocking, then catch up.
Tailscale on every device, signed in to the same account (free). In the admin console under DNS, turn on MagicDNS and HTTPS certificates.It gives every device a private address, so the server is never exposed to the internet.
A Chromium-based browser: Chrome, Brave, Edge, Helium, Vivaldi…The extension records and covers sites. On a Mac, browsers without it are hidden while sites are blocked.
An Android phone (optional)Phone app use, health, places and phone-side blocking.
An AI assistant with MCP (optional, recommended): Claude, Codex, ChatGPT…It turns raw app names into "what you're doing" and helps you set rules by just talking.

Linux window tracking needs KDE Plasma. On other desktops the Linux collector still records browser sites and AFK time, but not which app is in front.

1 · Start the server

01

  1. Run one script

    On the always-on machine, as your normal user (not root):

    $ curl -fsSL https://github.com/rimexe0/telemetry/releases/latest/download/install-server.sh | bash

    It checks what it needs and tells you how to fix anything missing. It creates every password and token, starts Postgres in Docker and the server as a background service, turns on nightly backups and self-updates, and publishes the server on your tailnet with tailscale serve. Running it again is safe: it keeps your data and secrets.

    If Tailscale says access denied, run this once, then run the script again:

    $ sudo tailscale set --operator=$USER

  2. Keep what it prints

    At the end you get:

    • the panel address, like https://your-server.your-tailnet.ts.net:8443/panel/
    • your panel token. It works like a password, so put it in your password manager.
    • the exact commands for steps 2–4, with your address already filled in.
    • a copy of all of it in ~/telemetry/setup.txt, in case you close the terminal.

  3. Open the panel

    Open the panel address on any device in your tailnet and paste the token. The panel stays empty until a device reports in.

2 · Your computers

02

  1. Run the installer

    On each Mac or Linux PC. It detects which one it's on:

    $ curl -fsSL https://github.com/rimexe0/telemetry/releases/latest/download/install.sh | bash

    Paste the server address when it asks, or set TELEMETRY_SERVER= before running it. It checks the release signature, installs the collector as a background service and keeps it updated from then on.

  2. Approve the device

    The panel shows a banner saying "… wants to connect". Click Connect. Each device gets its own key, and you can revoke it under Devices at any time.

  3. Mac only: two permissions

    Grant Accessibility to Telemetry Desktop when macOS asks (System Settings → Privacy & Security → Accessibility). That's how it reads the window in front and hides blocked apps. Then open your browser: the extension is installed by policy and turns itself on.

    Chrome on a Mac that isn't company-managed may refuse an extension installed by policy. If it doesn't show up, the installer tells you how to load it yourself in two clicks.

3 · Your phone

03

  1. Install the app

    Install Tailscale from the Play Store and sign in. Then download the Telemetry APK on the phone and open it. Android will ask you to allow installs from your browser once.

    download telemetry-phone.apk auto-update with Obtainium

  2. Pair it

    Open the app, type your server address (the same https://… one the server printed) and tap Connect. Then click Connect on the "wants to connect" banner in the panel.

  3. Grant what it asks for

    The app walks you through each permission: Usage access (app time), Accessibility (blocking), Notifications, and Health Connect if you want sleep and steps. Skip anything you don't want. The panel shows what's missing.

    Have a Mac and a USB cable? install-phone.sh grants everything adb can grant in one go, grayscale included.

4 · Your assistant recommended

04

Telemetry speaks MCP, so any assistant that supports MCP can read your day, propose labels and rules, and help you get back on track. The server prints these commands with your address and token filled in.

  1. Claude Code

    $ claude mcp add --scope user --transport http telemetry https://YOUR-SERVER/mcp --header "Authorization: Bearer YOUR-READ-TOKEN"

  2. Codex

    $ export TELEMETRY_MCP_TOKEN=YOUR-READ-TOKEN
$ codex mcp add telemetry --url https://YOUR-SERVER/mcp --bearer-token-env-var TELEMETRY_MCP_TOKEN

  3. Anything else

    Point any MCP client at https://YOUR-SERVER/mcp with the header Authorization: Bearer YOUR-READ-TOKEN.

  4. Let it read your day (optional)

    For the "what you're doing" readings and check-ins, the server needs a command that runs your assistant once per reading, like claude -p. Set it as TELEMETRY_INTENT_COMMAND in ~/telemetry/.env on the server and run the server script again. Everything else works without it.

5 · First rules

05

Nothing is blocked until you say so. Telemetry ships with no list of "bad" apps, because yours aren't the same as anyone else's.

  1. Watch for two or three days

    Let it collect, then look at Activity. The surprises are the useful part.

  2. Name your distractions

    Tell your assistant something like "YouTube, X and Reddit are my distractions, and the bank apps are essential". It proposes the labels, you approve them in chat, and they're applied. Or add them in the panel under Rules → Blocked apps.

  3. Choose distraction times

    Feeds stay closed outside them. Start generous and tighten it later: tightening is instant, while loosening waits a day.

  4. Hand over the key (when you're ready)

    Turn on the settings lock and let a friend type the PIN. The morning code, bedtime and openings are all in Rules too.

If something's off

06
The panel says a device is silent

Open Sources. It tells a sleeping device apart from a stopped collector. If a computer is on and still silent, run the installer again: it repairs the service without losing anything queued.

A site isn't blocked

Check that the extension is on in that browser profile. In private windows it stays off until you allow it. On a Mac, a browser without the extension is hidden while sites are blocked, so a missing extension can't be used as a way around the block.

The phone stopped reporting

Some phones put background apps to sleep. Set Telemetry's battery use to Unrestricted, and keep Tailscale connected. Everything collected in the meantime is delivered once it can reach the server again.

How do I update?

You don't need to. The server and the computers check for signed releases every 10 minutes, check that each update works, and roll it back if it doesn't. The phone updates through Obtainium.

How do I remove it?

Revoke the device under Devices so it can't send anything more. On Android, uninstall it like any other app. A one-command uninstaller for computers isn't there yet: the README lists the services the installer adds. Your history stays on the server until you delete its Docker volume.

Something else

Open an issue on GitHub, and say which device it happens on and what Sources shows for it.
